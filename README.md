# SQL Sales Analysis (SQLite)

A SQL portfolio project: a 4-table retail sales database analysed with joins, CTEs and window functions.

> **Data note:** the dataset is **synthetic**. It is randomly generated by `generate_data.py` (seeded, so it is reproducible) and is not real company data. Some patterns (for example heavy discounts hurting margin, and a few loss-making sub-categories) were built into the generator on purpose so the queries have something to find. Treat the findings below as a demonstration of method, not as real business conclusions.

## Schema
`customers` (250) · `products` (48) · `orders` (4,850) · `order_items` (8,359 lines)
`orders → customers`, `order_items → orders / products`. Sales and profit are computed in SQL from quantity, unit price, unit cost and discount.

## Files
| File | Purpose |
|---|---|
| `generate_data.py` | Builds `sales.db`, including 25 duplicate lines and 20 NULL discounts injected on purpose |
| `queries.sql` | Clean view `v_sales` plus 8 analysis queries |
| `run_queries.py` | Runs the queries and writes `results.md` |
| `results.md` | Output of every query |

## How to run
```bash
python generate_data.py
python run_queries.py
```
Needs Python 3 only (SQLite 3.25+ for window functions).

## What each query does
1. **Data quality checks:** duplicates, NULLs, orphan keys (found exactly the 25 duplicates and 20 NULLs injected)
2. **Region performance:** sales, profit, margin, share of total (`SUM() OVER ()`)
3. **Top 10 customers:** CTE + `RANK()`
4. **Year-over-year growth:** `LAG()`
5. **Sub-category profitability:** margin ranking with a `CASE` loss-making flag
6. **Discount impact:** margin by discount bucket
7. **Ship mode analysis:** order counts and average order value
8. **2025 monthly trend:** 3-month moving average and running YTD total (window frames)

## Findings on the synthetic data
- South is the largest region at 33.9% of sales; margins are similar across regions (21-22%).
- Sales grew every year, but growth slowed from 23.3% (2023) to 6.9% (2025).
- Tables and Binders are loss-making despite large sales; lines with discounts over 30% ran at a negative margin (-49%).
- Ship mode makes almost no difference to average order value.

## Cleaning approach
`v_sales` removes duplicate lines (`ROW_NUMBER()` per order + product) and treats missing discounts as 0. A real project would confirm that assumption with the data owner first.
